## 七、当前值得优先优化的点

### 1. 训练过程记录自动化

- 已实现训练开始摘要输出
- 已实现训练结束后自动写入 `training/tasks/crack_detection/reports/training_run_history.md`
- 后续可继续补充显存占用、最佳轮次、样例输出文件检查

### 2. 数据质量检查

- 抽样检查标签框是否贴合裂缝区域
- 检查是否存在漏标、错标、框过大、框过小的情况
- 若标注噪声较多，会直接影响最终上限

### 3. 类别策略优化

- 当前是单类别 `crack`，适合先快速做通
- 后续可尝试官方四分类训练，对比效果与展示价值
- 也可尝试加入 `China_Drone` 做 `v2`

### 4. 训练参数优化

- 若显存充足，可尝试更大的 `imgsz` 或更大的 `batch`
- 若训练后期指标仍持续上升，可适当增加 `epochs`
- 若过拟合明显，可考虑降低轮数、加强数据增强或调整早停策略

### 5. 推理端落地优化

- 训练完成后需要尽快验证单张图片推理速度
- 需要决定最终是直接使用 `.pt`，还是导出为 `onnx`
- 若后期要部署到非 Python 环境，建议补做导出测试

## 十、本轮训练输出图像与文件解读

以下文件位于 `training/tasks/crack_detection/weights/rdd_china_crack_only_v1/`，主要用于后续答辩展示、效果对照和调参分析。

### 1. 总体结果曲线

- `results.png`
  - 含义：展示 50 轮训练过程中训练损失、验证损失、`Precision`、`Recall`、`mAP50`、`mAP50-95` 的变化趋势。
  - 当前观察：
    - `train/box_loss` 从约 `2.11` 下降到 `1.03`
    - `train/cls_loss` 从约 `2.81` 下降到 `0.75`
    - `train/dfl_loss` 从约 `1.90` 下降到 `1.19`
    - `val/box_loss` 从约 `2.64` 下降到 `1.16`
    - `val/cls_loss` 从约 `11.44` 下降到 `0.75`
    - `val/dfl_loss` 从约 `2.53` 下降到 `1.23`
    - `Precision` 最终约 `0.89085`
    - `Recall` 最终约 `0.87750`
    - `mAP50` 最终约 `0.93065`
    - `mAP50-95` 最终约 `0.62526`
  - 说明：整体收敛趋势正常，没有明显训练崩坏。

### 2. 置信度与指标关系图

- `BoxF1_curve.png`
  - 含义：不同置信度阈值下的 F1 值变化。
  - 当前结果：最佳综合点约为 `F1 = 0.89`，对应阈值约 `0.459`。
  - 建议：后续推理默认置信度阈值可优先从 `0.45 ~ 0.50` 开始试。

- `BoxP_curve.png`
  - 含义：不同置信度阈值下的 Precision 变化。
  - 当前结果：当阈值升高时，Precision 持续升高，在较高阈值下接近 `1.00`。
  - 说明：阈值越高，误检越少，但也更容易漏检。

- `BoxR_curve.png`
  - 含义：不同置信度阈值下的 Recall 变化。
  - 当前结果：低阈值时 Recall 较高，阈值升高后 Recall 明显下降。
  - 说明：这符合检测任务规律，阈值越严格，漏检通常越多。

- `BoxPR_curve.png`
  - 含义：Precision-Recall 曲线，用于观察不同召回水平下的查准率变化。
  - 当前结果：曲线整体靠近右上区域，对应 `mAP@0.5 = 0.931`。
  - 说明：当前模型在单类别裂缝检测任务上已经具备较好的识别能力。

### 3. 混淆矩阵图

- `confusion_matrix.png`
  - 含义：展示真实类别与预测类别之间的对应关系。
  - 当前结果：
    - 真实为 `crack` 且预测为 `crack`：`790`
    - 真实为 `background` 但预测为 `crack`：`219`
    - 真实为 `crack` 但预测为 `background`：`59`
  - 说明：
    - `790` 代表较多裂缝被正确检出
    - `59` 代表存在一定漏检
    - `219` 代表存在一定误检或多检

- `confusion_matrix_normalized.png`
  - 含义：将混淆矩阵按比例归一化，更方便看占比。
  - 当前结果：
    - `crack -> crack` 约 `0.93`
    - `crack -> background` 约 `0.07`
    - `background -> crack` 接近 `1.00` 的显示反映了背景误检占比问题
  - 说明：当前模型对裂缝本身识别较强，但仍需在真实图片中重点排查误检来源。

### 4. 数据标注分布图

- `labels.jpg`
  - 含义：展示训练数据中标签数量、框位置分布、框宽高分布。
  - 当前结果：
    - 标注实例总数约 `3566`
    - 只有一个类别：`crack`
    - 裂缝框多为细长形，符合裂缝目标特征
  - 说明：数据分布整体合理，但框形态偏细长，后续需注意模型对细裂缝和长裂缝的泛化能力。

### 5. 训练批次与验证批次可视化图

- `train_batch0.jpg`、`train_batch1.jpg`、`train_batch2.jpg`
  - 含义：展示训练阶段抽样图片与真实标注框。
  - 作用：检查训练输入是否正常、标注框是否大致合理。

- `train_batch3720.jpg`、`train_batch3721.jpg`、`train_batch3722.jpg`
  - 含义：通常是训练后期抽样批次可视化图。
  - 作用：辅助观察增强后的训练样本形态。

- `val_batch0_labels.jpg`、`val_batch1_labels.jpg`、`val_batch2_labels.jpg`
  - 含义：验证集真实标注框可视化图。
  - 作用：查看验证集标签质量与框位置是否合理。

- `val_batch0_pred.jpg`、`val_batch1_pred.jpg`、`val_batch2_pred.jpg`
  - 含义：验证集预测结果可视化图。
  - 作用：直观看模型预测框与真实裂缝位置是否接近。
  - 当前观察：已经能检测出较多明显裂缝，但框尺度和局部细节还可继续优化。

### 6. 关键权重文件

- `weights/best.pt`
  - 含义：验证集表现最好的模型权重。
  - 用途：后续推理、部署、系统调用优先使用此文件。

- `weights/last.pt`
  - 含义：最后一轮训练结束时保存的模型权重。
  - 用途：适合断点续训，不一定优于 `best.pt`。
