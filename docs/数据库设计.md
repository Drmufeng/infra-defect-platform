# 数据库设计

本文档用于说明当前项目后端所使用的 PostgreSQL 数据库设计，便于后续开发、联调、答辩展示和平台扩展。

## 一、数据库基本信息

- 数据库类型：`PostgreSQL`
- 数据库名称：`infra_defect_platform`
- 当前定位：基础设施病害智能检测与管理平台数据库
- 当前首个落地任务：道路裂缝检测
- 默认管理员账号：`admin`
- 默认管理员初始密码：`1234`

说明：当前数据库命名已完成平台化统一，便于后续扩展桥梁、房屋、隧道等多类基础设施病害任务。

## 二、设计目标

当前数据库主要服务以下业务场景：

- 管理数据集版本
- 管理训练任务与训练指标
- 管理模型版本与默认模型
- 管理推理测试任务与测试结果
- 统一管理数据集、训练、推理产生的文件资产（权重、日志、报告、结果图）
- 管理系统配置项
- 为后续用户管理、检测记录归档、多任务扩展预留空间

## 三、核心表设计

### 1. `users`

用途：存放后台用户信息。

核心字段：

- `id`：主键
- `username`：用户名，唯一
- `password_hash`：密码哈希
- `role`：角色，当前默认 `admin`
- `status`：账号状态，例如 `active`、`disabled`
- `created_at`：创建时间
- `updated_at`：更新时间

### 2. `datasets`

用途：管理数据集版本与数据来源信息。

核心字段：

- `id`：主键
- `name`：数据集名称，例如 `rdd_china_crack_only_v1`
- `task_type`：任务类型，当前默认 `infrastructure_defect_detection`
- `version`：版本号，例如 `v1`
- `source_type`：数据来源，例如 `China_MotorBike`
- `label_strategy`：标签策略，例如 `crack_only`
- `run_id`：数据集运行 ID，用于和文件目录、清单文件一一对应
- `raw_path`：原始数据目录路径
- `processed_path`：处理后数据目录路径
- `manifest_path`：数据集清单文件路径
- `train_count`：训练集数量
- `val_count`：验证集数量
- `class_names`：类别名称集合
- `status`：状态
- `remark`：备注
- `created_by`：创建人
- `created_at`：创建时间
- `updated_at`：更新时间

### 3. `training_jobs`

用途：记录每次训练任务的参数与执行状态。

核心字段：

- `id`：主键
- `job_name`：训练任务名称
- `run_id`：训练运行 ID
- `dataset_id`：关联的数据集 ID
- `model_id`：关联模型 ID（例如增量训练或继续训练场景）
- `base_weight`：预训练权重路径
- `epochs`：训练轮数
- `batch_size`：批大小
- `image_size`：输入图像尺寸
- `device`：训练设备
- `workers`：数据读取线程数
- `patience`：早停轮数
- `status`：任务状态
- `log_path`：日志路径
- `output_dir`：训练输出目录
- `manifest_path`：训练清单文件路径
- `error_message`：失败原因
- `created_by`：创建人
- `started_at`：开始时间
- `finished_at`：结束时间
- `created_at`：创建时间
- `updated_at`：更新时间

### 3.1 `dataset_files`

用途：记录数据集中单张图片及其标签文件的元数据，用于后续做文件级管理、抽样分析与质量检查。

核心字段：

- `id`
- `dataset_id`
- `file_name`
- `image_path`
- `label_path`
- `split`
- `width`
- `height`
- `file_hash`
- `file_size`
- `remark`
- `created_at`

### 4. `training_metrics`

用途：记录训练结果汇总指标。

核心字段：

- `id`：主键
- `training_job_id`：关联训练任务 ID
- `precision`
- `recall`
- `map50`
- `map50_95`
- `box_loss`
- `cls_loss`
- `dfl_loss`
- `best_epoch`
- `results_csv_path`：训练指标文件路径
- `created_at`

### 5. `models`

用途：管理模型版本记录。

核心字段：

- `id`：主键
- `name`：模型名称，例如 `best.pt`
- `task_type`：任务类型
- `dataset_id`：关联数据集 ID
- `training_job_id`：关联训练任务 ID
- `weight_path`：模型权重路径
- `model_type`：模型框架类型，例如 `yolov8`
- `model_code`：模型编码，用于客户端选择模型
- `publish_status`：发布状态，例如 `draft`、`published`、`archived`
- `published_at`：发布时间
- `metric_summary`：指标摘要
- `is_default`：是否为默认模型
- `status`：状态
- `created_by`：创建人
- `created_at`
- `updated_at`

### 6. `inference_tasks`

用途：记录一次推理测试任务。

核心字段：

- `id`：主键
- `run_id`：推理运行 ID
- `model_id`：关联模型 ID
- `source_type`：测试来源，例如 `manual`
- `input_path`：输入目录或文件路径
- `output_path`：输出目录路径
- `report_path`：报告路径
- `manifest_path`：推理清单文件路径
- `conf_threshold`：置信度阈值
- `status`：任务状态
- `summary_json`：推理任务摘要 JSON
- `error_message`：失败原因
- `created_by`：创建人
- `started_at`：开始时间
- `finished_at`：结束时间
- `created_at`
- `updated_at`

### 7. `inference_results`

用途：记录单张图片的推理结果汇总。

核心字段：

- `id`：主键
- `inference_task_id`：关联推理任务 ID
- `image_name`：图片文件名
- `image_path`：原图路径
- `result_image_path`：结果图路径
- `detected_count`：检测目标数量
- `latency_ms`：单图推理耗时（毫秒）
- `summary_json`：当前图片检测结果摘要
- `created_at`

### 7.1 `detections`

用途：记录单张推理结果中的逐框检测信息，便于后续做目标级分析、统计与前端详情展示。

核心字段：

- `id`
- `inference_result_id`
- `class_name`
- `confidence`
- `x1`
- `y1`
- `x2`
- `y2`
- `created_at`

### 7.2 `artifact_files`

用途：统一登记平台中的文件资产，支持前端按任务查看并下载训练产物、推理结果和报告。

核心字段：

- `id`
- `owner_type`：归属类型，例如 `dataset`、`training_job`、`inference_task`、`model`
- `owner_id`：归属对象 ID
- `dataset_id` / `training_job_id` / `inference_task_id` / `model_id`：可选关联字段
- `file_name`
- `file_path`
- `file_type`
- `mime_type`
- `file_size`
- `sha256`
- `remark`
- `created_by`
- `created_at`

### 8. `system_settings`

用途：统一保存系统级配置项。

核心字段：

- `id`：主键
- `setting_key`：配置键
- `setting_value`：配置值
- `description`：说明
- `created_at`
- `updated_at`：更新时间（建议后续补齐到模型中）

### 9. `audit_logs`

用途：记录登录、模型调用、客户端结果回传、系统初始化等关键操作，用于后台审计与答辩演示。

核心字段：

- `id`
- `actor_id`
- `actor_name`
- `actor_role`
- `action`
- `target_type`
- `target_id`
- `request_id`
- `ip`
- `user_agent`
- `detail_json`
- `created_at`

## 四、表关系说明

当前主要关系如下：

- 一个 `datasets` 可以关联多个 `training_jobs`
- 一个 `datasets` 可以关联多条 `dataset_files`
- 一个 `training_jobs` 可以对应一条或多条 `training_metrics`
- 一个 `training_jobs` 可以产出多个 `models`
- 一个 `models` 可以被多个 `inference_tasks` 使用
- 一个 `inference_tasks` 可以包含多条 `inference_results`
- 一个 `inference_results` 可以包含多条 `detections`
- 一个业务对象（数据集/训练任务/推理任务/模型）可以关联多条 `artifact_files`
- 一个 `users` 可以产生多条 `audit_logs`

## 五、当前设计特点

- 平台化命名，不把系统锁死在单一裂缝任务上
- 图片、模型、结果图等大文件仍然保存在磁盘中，数据库只保存路径和结构化元数据
- 训练指标单独结构化存储，便于前端直接展示与对比
- 推理结果使用任务表 + 明细表设计，便于后续做历史记录查询
- 已补充数据集文件表与检测框表，便于后续向更精细的数据治理和结果分析扩展
- 已补充统一文件资产表，可沉淀权重、日志、报告、结果图等产物元数据
- 已补充鉴权与审计相关字段，便于平台从原型过渡到可运营状态
