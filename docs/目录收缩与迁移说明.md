# 目录收缩与迁移说明

说明：本文档记录的是“训练工作区收缩”的历史阶段。文中出现的 `backend/`、`frontend/`、`client/` 为历史结构，不代表当前正式目录。当前平台主结构已升级为三端布局，请优先参考：`docs/三端架构与迁移计划.md`。

本次调整的目标，是将前期过度拆分的训练与实验结构进行收缩，形成更适合“平台开发 + 多模型方向扩展”的目录布局。

## 一、调整目标

当前推荐的核心目录为：

- `datasets/`
- `training/`
- `backend/`
- `frontend/`
- `client/`

其中：

- `datasets/`：统一管理原始数据、处理后数据和测试图片
- `training/`：统一管理训练代码、训练配置、权重、实验报告与分析记录
- `backend/`：平台后端接口与数据库服务
- `frontend/`：平台 Web 管理端
- `client/`：后续可扩展的桌面端或轻客户端

## 二、本次迁移内容

已完成以下迁移：

- `training/scripts/*.py` -> `training/tasks/crack_detection/scripts/`
- `training/configs/*.yaml` -> `training/tasks/crack_detection/configs/`
- `models/weights/rdd_china_crack_only_v1/` -> `training/tasks/crack_detection/weights/rdd_china_crack_only_v1/`
- `training/reports/training_run_history.md` -> `training/tasks/crack_detection/reports/training_run_history.md`
- `training/reports/test_images_inference/` -> `training/tasks/crack_detection/reports/test_images_inference/`
- `docs/训练记录与优化建议.md` -> `training/tasks/crack_detection/docs/训练记录与优化建议.md`

## 三、调整后的好处

- 训练脚本与后端服务不再混杂
- 模型权重不再单独作为顶层目录维护
- 同一任务方向的代码、配置、产物、文档统一放在一起
- 后续扩展新任务时，可直接新增 `training/tasks/<task_name>/`

## 四、后续建议

- 后续逐步减少对旧 `models/` 空目录的依赖
- 若增加坑槽检测或多病害任务，可直接按同样结构新增任务目录
- 平台级文档继续保留在 `docs/`，任务级实验与训练文档收归各任务目录
