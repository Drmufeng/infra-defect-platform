# 三端架构与迁移计划（V1.5）

本文档用于明确三端边界、路由边界和目录迁移规则，保证比赛期快速迭代时不再出现“功能混塞到同一前端”的问题。

当前正式项目根目录：`B:\infra-defect-platform`

## 一、三端职责边界

- `apps/admin-web/`：管理端
  - 面向管理员和运营人员
  - 负责用户、模型、任务、报告、系统设置、审计等管理能力

- `apps/client-web/`：客户端
  - 面向业务使用者
  - 负责模型选择、任务发起、结果查看、报告下载/回传

- `apps/api-server/`：后端服务
  - 统一提供系统、管理、客户端接口
  - 负责鉴权、任务状态、数据存储、审计与资产管理

## 二、后端路由边界

当前已完成：

- `app/api/admin/`：后台管理接口（数据集、训练、模型、测试）
- `app/api/client/`：客户端接入接口（配置下发、结果回传）
- `app/api/system/`：基础系统接口（health/overview/settings）

当前代表性路径：

- `POST /api/auth/login`
- `GET /api/auth/me`
- `GET /api/health`
- `GET /api/overview`
- `GET /api/admin/datasets`
- `GET /api/admin/models`
- `GET /api/admin/artifacts`
- `GET /api/admin/audit-logs`
- `GET /api/admin/testing/tasks`
- `GET /api/client/access/profile`
- `POST /api/client/access/reports`

当前默认开发端口：

- admin-web：`5500`
- client-web：`5180`
- api-server：`2048`

当前部署准备：

- 后端环境变量模板：`apps/api-server/.env.example`
- 前端环境变量模板：`apps/admin-web/.env.example`、`apps/client-web/.env.example`
- Docker 编排：`docker-compose.yml`

## 三、目录迁移结果

已完成（历史目录已收口到正式结构）：

- `backend/ -> apps/api-server/`
- `frontend/ -> apps/admin-web/`
- `client/ -> apps/client-web/`（已落地标准前端项目结构）

当前新项目根目录 `B:\infra-defect-platform` 已仅保留标准化后的正式目录结构，不再携带旧兼容目录；旧 `B:\dome` 目录已清空，待会话释放后可删除空目录壳。

新增：

- `storage/uploads/`
- `storage/inference-results/`
- `storage/reports/`
- `scripts/`

## 四、存储规范

平台运行产物统一写入仓库根目录 `storage/`：

- 上传原图：`storage/uploads/`
- 推理结果：`storage/inference-results/`
- 报告文件：`storage/reports/`

训练工作区仍保持独立：

- `training/` 仅用于训练实验、权重与实验报告归档
- 平台运行产物不再与训练工作区混写

## 五、验收标准

- admin-web 可启动并拉取后端数据
- api-server 可启动并访问 `/api/health`
- client-web 可启动并调用至少一个业务接口（`/api/client/access/profile`）
- `storage/` 目录结构与后端配置一致
- 文档路径与代码路径一致
