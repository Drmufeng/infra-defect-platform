# 云服务器部署流程

本文档提供一套面向 Linux 云服务器的标准部署流程，适合将当前项目从本地开发环境迁移到测试环境或生产环境。

## 一、推荐部署方式

当前推荐采用：

- 云服务器系统：`Ubuntu 22.04 LTS` 或 `Debian 12`
- 服务编排：`Docker Compose`
- 反向代理：`Nginx`
- 数据库：`PostgreSQL`（容器内或云数据库）

推荐原因：

- 目录结构清晰
- 部署步骤可重复
- 便于后续扩展 Redis、异步任务、对象存储等组件

## 二、服务器准备

建议的最小配置：

- CPU：2 核
- 内存：4 GB
- 磁盘：40 GB
- 系统：Ubuntu 22.04+

开放端口建议：

- `22`：SSH
- `80`：HTTP
- `443`：HTTPS
- 如需临时直连调试，可短期开启：`2048`、`5500`、`5180`

生产环境不建议直接暴露 `2048/5500/5180` 到公网，应通过 Nginx 统一代理。

## 三、安装基础依赖

```bash
sudo apt update
sudo apt install -y git curl ca-certificates gnupg lsb-release
```

安装 Docker：

```bash
curl -fsSL https://get.docker.com | sh
sudo systemctl enable docker
sudo systemctl start docker
sudo docker --version
```

安装 Docker Compose 插件：

```bash
docker compose version
```

## 四、拉取项目代码

建议部署目录：

```bash
sudo mkdir -p /srv/infra-defect-platform
sudo chown -R $USER:$USER /srv/infra-defect-platform
cd /srv/infra-defect-platform
git clone <你的私有仓库地址> .
```

## 五、准备环境变量

复制模板：

```bash
cp .env.example .env
cp apps/api-server/.env.example apps/api-server/.env
```

重点检查并修改：

### 1. 根目录 `.env`

- `POSTGRES_PASSWORD`
- `AUTH_SECRET_KEY`
- `INITIAL_ADMIN_PASSWORD`
- `ADMIN_VITE_API_BASE_URL`
- `CLIENT_VITE_API_BASE_URL`

### 2. 后端 `apps/api-server/.env`

若使用云数据库，建议直接填写：

```env
DATABASE_URL=postgresql+psycopg://user:password@host:5432/infra_defect_platform
```

若使用 Compose 自带 PostgreSQL，可保持：

```env
POSTGRES_HOST=postgres
POSTGRES_PORT=5432
POSTGRES_USER=postgres
POSTGRES_PASSWORD=你的数据库密码
DATABASE_NAME=infra_defect_platform
```

建议生产环境同步调整：

```env
DOCS_ENABLED=false
CORS_ORIGINS=https://admin.example.com,https://client.example.com
INITIAL_ADMIN_PASSWORD=强密码
AUTH_SECRET_KEY=强随机字符串
```

## 六、使用 Docker Compose 启动

在项目根目录执行：

```bash
docker compose up --build -d
```

查看运行状态：

```bash
docker compose ps
docker compose logs -f api-server
```

首次启动后建议检查：

- `postgres` 容器是否正常
- `api-server` 是否执行了 `python -m app.db.init_db`
- `admin-web`、`client-web` 是否构建成功

## 七、基础验证

### 1. 后端健康检查

```bash
curl http://127.0.0.1:2048/api/health
```

期望返回：

```json
{"status":"ok"}
```

### 2. 后台登录验证

默认初始账号：

- 用户名：`admin`
- 密码：以 `.env` 中 `INITIAL_ADMIN_PASSWORD` 为准

### 3. 文档与页面验证

- 后端文档：`/docs`（如未关闭）
- 管理端：首页可正常打开
- 客户端：首页可正常打开

## 八、Nginx 反向代理建议

推荐域名规划：

- `admin.example.com` -> 管理端
- `client.example.com` -> 客户端
- `api.example.com` -> 后端 API

或单域名方案：

- `example.com/admin` -> 管理端
- `example.com/client` -> 客户端
- `example.com/api` -> 后端

推荐优先用独立子域名，路径更清晰，前后端配置更简单。

## 九、升级发布流程

更新代码后：

```bash
cd /srv/infra-defect-platform
git pull
docker compose up --build -d
```

如需仅重启后端：

```bash
docker compose up --build -d api-server
```

## 十、数据与目录规划

建议把以下目录挂载到持久化存储：

- `storage/`
- `datasets/`
- `training/`

其中：

- `storage/`：平台运行产物
- `datasets/`：数据集原始与处理结果
- `training/`：训练工作区、权重与实验记录

## 十一、生产环境上线前检查清单

- 将 `INITIAL_ADMIN_PASSWORD` 改为强密码
- 将 `AUTH_SECRET_KEY` 改为强随机字符串
- 配置 HTTPS
- 收紧 `CORS_ORIGINS`
- 如非必要，关闭 `DOCS_ENABLED`
- 配置数据库备份
- 配置 `storage/` 与模型权重备份
- 确认日志、磁盘和 GPU 使用情况
